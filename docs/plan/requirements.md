# 要件定義

> 次の構成で「誰が・何を・どこまで」できるか、守ること、範囲外。画面ごとの中身は [画面設計](screens.md)、データの形は [データ設計](data-model.md)、決まっていないことは [決めること](decisions.md)。
> 2026-11-06 時点の案。

---

## 1. 使う人と権限

| 使う人 | ログイン | できること | できないこと |
|---|---|---|---|
| 見る人（採用担当・面接官など） | しない | 公開ページを見る。公開を許した場合だけスキルシートを保存する | 非公開の項目・他の人の編集中のデータを見る |
| 本人（登録したユーザー） | する | 自分のプロフィール・スキル・職務経歴の編集・保存・公開、Excel の読み込み・書き出し、表示の設定、版を戻す、退会 | 他の人のデータを見る・変える |
| 管理者 | ─ | 置かない（運用は Firebase / Google Cloud のコンソールで行う） | ─ |

- 新規登録を**誰でもできるようにするか、自分だけにするか**は未決（[D-03](decisions.md#d-03-新規登録を誰に開くか)）。無料枠と迷惑な登録を考えると、最初は招待（決めたメールアドレスだけ）がおすすめ。

## 2. 機能の要件

### 2.1 認証（Phoenix）

| ID | 要件 |
|---|---|
| AUTH-01 | メールアドレスとパスワードで登録する。確認のメールを送る |
| AUTH-02 | ログイン・ログアウトする。ログアウトしたら、そのトークンは使えなくする |
| AUTH-03 | パスワードを忘れたら、メールで再設定する。ログイン中はパスワードを変えられる |
| AUTH-04 | ログインすると、API で使うトークン（短い期限）と、更新用のトークンを発行する。API はトークンを確かめてから処理する |
| AUTH-05 | 続けて失敗したら、しばらくログインできなくする（総当たりの対策） |
| AUTH-06 | 退会すると、アカウントとすべてのデータ（版・公開ページを含む）を消す |

認証の形（パスワードをどこで持つか）は [D-01](decisions.md#d-01-認証の形) で決める。

### 2.2 マイページの API（Hono）

| ID | 要件 |
|---|---|
| API-01 | プロフィール（Home / About・スキルシートだけの項目）を取得・更新する |
| API-02 | スキル（主な技術・技術の分類）を取得・更新する。プロジェクトから集計する部分は今と同じ |
| API-03 | 職務経歴（Work / Private のプロジェクト）を取得・追加・更新・削除・並び替えする |
| API-04 | Home の表示設定を取得・更新する |
| API-05 | 編集中のデータを自動で保存する（下書き）。別のタブ・端末で同時に変えたときは、上書きせずに知らせる |
| API-06 | 「保存」で版を作る。版の一覧を見て、前の版に戻す |
| API-07 | 「公開」で、選んだ版から公開する項目だけを取り出して公開ページを作る。公開を止める |
| API-08 | 受け取ったデータは必ずサーバーで形を確かめる（画面の確かめだけに頼らない） |

### 2.3 Excel（FastAPI・ブラウザ）

| ID | 要件 |
|---|---|
| XLS-01 | スキルシート（Excel）を読み込み、プロフィール・職務経歴に変換して、確認画面のあとで編集中のデータに入れる |
| XLS-02 | 保存した版から、テンプレートの書式のままスキルシート（Excel）と PDF を作る |
| XLS-03 | 読み込みの誤りは、何行目・何件目かを付けて見せる（今と同じ） |
| XLS-04 | どの処理をブラウザで、どれを FastAPI でやるかは比べて決める（[D-06](decisions.md#d-06-fastapi-に任せる範囲)） |

### 2.4 公開ページ（Flutter）

| ID | 要件 |
|---|---|
| PUB-01 | 公開した版を、ログインなしで URL から見られる。中身は今の Home・About・Skills・Projects |
| PUB-02 | 表示設定で隠した項目・セクション・プロジェクトは、データとしても公開ページに入れない（画面で隠すだけにしない） |
| PUB-03 | スキルシートだけの項目（ふりがな・性別・生年月日など）は、表示設定によらず**絶対に公開しない** |
| PUB-04 | 公開していない・存在しない URL は「見つかりません」を出す（ユーザーがいるかどうかを区別しない） |

## 3. 守ること（機能以外の要件）

| 分類 | 要件 |
|---|---|
| 費用 | **完全に無料**。無料枠を超えない設定（最小インスタンス 0・最大 1〜2、イメージの自動削除など）にし、予算のアラートと、超えたときに止める仕組みを置く（[サービスの構成](architecture.md#4-無料枠と守り方)） |
| 個人情報 | 非公開の項目はログインした本人だけが読める。ログに個人情報（メールアドレス・プロフィールの中身）を出さない。リポジトリ・Docker イメージに個人のデータを入れない（今と同じ） |
| 安全 | 通信は HTTPS。トークンは短い期限＋更新。Firestore は本人以外が読み書きできないルールにし、ルールのテストを CI で動かす。依存関係は Dependabot で更新する |
| 速さ | 公開ページは今と同じ体感（[パフォーマンス](../performance.md)）。API は止まっている状態からの起動（コールドスタート）を含めて 95% が 2 秒以内（案） |
| 可用性 | 公開ページと API の成功率 99%／月（案。無料枠なので高くしすぎない）。SLO として測る |
| 運用 | ログは JSON で Cloud Logging へ。死活の確認・エラー率・応答時間を Cloud Monitoring で見る。アクセスは GA4、集計は BigQuery |
| 変えやすさ | サービスごとにテストと Dockerfile を持つ。ローカルは `docker compose up` だけで全部が動く。Firebase は Emulator で代わりにする |
| 端末 | 今と同じ（320px〜、PC・タブレット・スマホ、ライト / ダーク） |

## 4. 範囲外（今回はやらない）

- 電話番号（SMS）でのログイン（無料プランで使えない）。
- 複数人での同時編集・コメント・共有の権限。
- 管理者の画面、課金、独自ドメイン（ドメインは費用がかかる）。
- ネイティブアプリ（iOS / Android）。

## 5. 今あるものの扱い

| 今あるもの | 扱い |
|---|---|
| 画面（Home・About・Skills・Projects・案件の詳細） | 公開ページとしてそのまま使う。データの取り方だけ Repository 経由に変える |
| 入力の画面（アップロード・［データ］・入力フォーム・確認画面） | マイページの編集に移す。確認画面を挟む流れは変えない |
| データの形（YAML / Markdown のテンプレート、`Profile`・`Project`） | Firestore の項目の元にする（[データ設計](data-model.md)） |
| Excel の読み込み・書き出し・PDF（`skill_sheet*.dart`） | まずはそのまま使い、FastAPI に移すかは比べて決める |
| shelf の backend | Hono に置き換えて消す |
| テスト・網羅率 90%・CI | 続ける。サービスごとのテストと、Emulator を使ったテストを足す |
| GitHub Pages へのデプロイ | 新しい配信先が動くまで残す |
