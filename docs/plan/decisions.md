## D-01 認証の形

> **決定（2026-11-06）：B**。段階 4 で `services/auth-phoenix/` として作った。パスワードは Firebase Auth が持ち、Phoenix は REST を呼ぶ窓口（入力の確認・登録できる人の制限・総当たりの対策・すべての端末からのログアウト・JSON のログ）。発行されるのは Firebase の ID トークンなので、Hono は変えていない。

| 案 | 中身 | よいところ | 気になるところ |
|---|---|---|---|
| A | 画面から Firebase Auth を直接使う。Phoenix は認証以外に使う | いちばん簡単で安全 | 「Phoenix で認証を作る」にならない |
| **B（おすすめ）** | Phoenix が Firebase Auth の REST API を使って登録・ログイン・再設定を行い、トークンを渡す。パスワードは Firebase が持つ | パスワードを自分で持たない。Phoenix に総当たりの対策・ログ・ログアウト（トークンの取り消し）を作れる。Hono は Firebase のトークンを確かめるだけ。Auth Emulator でローカルでも動く | Firebase の API の制約に合わせる |
| C | Phoenix で全部作る（パスワードのハッシュ・利用者の保存・トークンの署名） | 学べることがいちばん多い | パスワードを自分で守る責任。利用者の置き場所が要る（無料なら Firestore）。Hono が Phoenix の公開鍵で確かめる仕組みも要る |

## D-02 Hono を動かす場所

| 案 | よいところ | 気になるところ |
|---|---|---|
| Cloudflare Workers | 無料・カード不要、エッジで速い、公開ページのキャッシュがしやすい | Firebase Admin SDK が動かない。Firestore は REST API＋サービスアカウントの JWT（Web Crypto で署名）でつなぐ |
| Cloud Run（Node） | Admin SDK が使える、ほかのサービスとそろう | コールドスタート、Artifact Registry の容量 |

案：Hono はどちらでも動くので、Firestore へのつなぎ方を 1 か所にまとめ、ローカルは Node で動かす。本番は Workers にする。

## D-03 新規登録を誰に開くか

| 案 | 中身 |

## D-06 FastAPI に任せる範囲

今の Flutter には、Excel の読み込み・Excel と PDF の書き出しが**ブラウザで動くものがある**（`skill_sheet*.dart`）。

| 処理 | ブラウザ（今） | FastAPI に移すと |
|---|---|---|
| Excel の読み込み | 動く。ファイルを外に出さない | サーバーでも形を確かめられる（ただし Hono でデータの形は確かめる） |
| Excel・PDF の書き出し | 動く。ただしライブラリ（excel・pdf・フォント）で最初の読み込みが重い | 画面が軽くなる。見る人へのスキルシートの配布（[表示設定](screens.md#m-06-home-の表示設定)）をサーバーで作れる |

**決定（2026-11-08）：FastAPI には、公開ページを見る人向けのスキルシート（Excel・PDF）を作ることだけを任せる（`services/excel-fastapi/`）。形は本人がダウンロードするものと同じ（Excel のテンプレート、PDF はその見た目のまま）で、作るのはブラウザと同じ Dart の処理（`dart compile exe` したコマンドを FastAPI が呼ぶ）。** Excel の読み込みと、本人がダウンロードする Excel・PDF はブラウザのまま。比べた結果は [Excel：ブラウザか FastAPI か](excel.md)。決め手は、スキルシートの個人の情報をサーバーに送らずに済むこと、Python で同じ見た目を作り直すと実装が 2 つになること、見る人向けのスキルシート は決まった URL で配れるとよいこと。FastAPI は Firestore につながず、API（Hono）から公開ページのデータを受け取る。

## D-07 リージョン

- Firestore の場所は**後から変えられない**。使う人が日本にいるので東京（`asia-northeast1`）が速い。
- Cloud Run の無料枠は us-central1 の料金を元に数える。Cloud Storage の無料枠は `us-central1`・`us-west1`・`us-east1` だけ。デプロイの前に、使うリージョンで無料枠がどう数えられるかを公式のページで確かめる。

## D-08 URL の形とトップに出すもの

- 公開ページ：`/u/{slug}`（案）。
- トップ（`/`）：**サイトの持ち主の公開ページ**（今の GitHub Pages と同じ見え方。案）か、サービスの紹介とログイン。
- URL の切り替えは go_router で行う（段階 1）。Flutter Web は URL を `#` なし（path）にし、配信先で全部の URL を `index.html` に向ける。

## D-10 公開する項目の既定

- スキルシートだけの項目（ふりがな・性別・生年月日・国籍・配偶者・最寄駅・学歴）は**常に公開しない**（設定でも出せない。案）。
- ほかの項目は、最初は今の公開ページと同じく全部出し、表示設定で隠す。
- プロジェクトのリンク・規模（会社の情報が分かることがある）を最初から隠すかも決める。
